1. Overview

Invest IQ is the single front door of the InvestIQ multi-agent ecosystem: it understands user intent, routes each request to exactly one specialist owner, combines returned results and reports one consolidated answer. It never analyzes on its own - it does not do equity research, MF research, planning, git or agent-file work by default Verified (.opencode\agent\invest-iq.md, read 20-Oct-2026).

The ecosystem is a repository-local set of flat agent files under .opencode\agent\, three owned skills under .opencode\skills\, and a Layer 0 runtime rulebook at governance\rules.md. Content HTML lives under Developer_file\ and reaches readers only through the approval-gated mirror into APP\ Verified (folder listings 20-Oct-2026).

Agent families Derived from the seven inspected agent files

Orchestration (1)

invest-iq - the only parent/orchestrator and routing authority (Layer 1). Classifies, delegates, validates, consolidates.

Work specialists (3)

equity-analyst, mutual-fund-analyst, portfolio-planner - do the investment-content work inside strict ownership boundaries, each with its own skill playbook.

Meta agents (2)

agent-builder-governance - sole authority for agent/skill files and compliance; architecture-explorer - documents the architecture (this handbook), never changes the system.

Repository agent (1)

github-agent - read-only git inspection by default; every git mutation is approval-gated, per action; git init forbidden.

Evidence labels are used consistently throughout (Verified Derived VERIFY Unverified); the legend also sits in the left navigation.

9. Ground Rules

10. What Works vs Common Pitfalls

What works (evidence + governance practice)

  • Single-purpose agents - each file defines one responsibility and explicit boundaries; easy to audit Derived (all seven agent files).
  • File-based handoffs - hub pages, marker-delimited generated blocks and dated journal rows are the integration surface; no hidden shared memory Derived (skills).
  • Explicit routing table - one source of truth in invest-iq.md, never routed from documentation Verified.
  • Approval gates at the moment of the gate - publish/git/config/structure changes stop and ask; nothing mutates silently Verified (Layer 0 rule 7).
  • Owned skills - playbooks live next to their owner; no cross-agent improvisation Verified (3 skills, 3 owners).
  • Append-only dated journals - history is immutable; several runs per month coexist Verified (equity + MF skills).
  • Scripted QA - qa_check.py target PASS before any publish claim Verified (skills + script present).

Common pitfalls to avoid

  • Parent analyzing - invest-iq absorbing specialist work instead of routing it; blurs ownership Derived (invest-iq rules).
  • Stale data presented as current - quoting a CMP/NAV without its date, or carrying a stale peer list into a new period Verified prohibition (rule 6; MF rule 3a).
  • Silent overrides - editing old journal rows, hardcoding badge counts, or changing a rules-pack number without the user Verified prohibition (skills; planner rule 3).
  • Vague verdicts - merging the three MF verdicts into one score, or guessing a score where data is missing Verified prohibition (MF non-negotiable rule 9).
  • No change log - agent/rules-pack edits without re-read, restart reminder or record Verified prohibition (rules 7, 13).
  • Hand-editing APP\ or publishing without a fresh yes Verified prohibition (rule 10).
  • Reading Docs\ for routing/identity - documentation drift becoming runtime truth Verified prohibition (rule 11).
