How this hub works

Codes: every report registers the same option code in both its own #fundSel and this hub's — NAME | CAT | STATUS | GOALS (status field: H = HOLDING, C = CANDIDATE; GOALS = the workbook goal codes the fund is invested against, e.g. ABSLMULTI | MC | H | CC,FF — one report per fund even when it serves two goals). Badges above are computed from these option codes.

Verdicts (09-Oct-2026): three separate cards — Fund Quality (seven weighted metrics, 0–100, bands Strong 80–100 / Acceptable 65–79 / Under Review 50–64 / Weak <50, labelled provisional), SIP Outcome (invested / value / P&L / XIRR from real dated cash flows, or an explicit Insufficient Evidence state) and Investor Action (Continue / Continue and Monitor / Review Allocation / Consider Switching / Insufficient Evidence) — never merged into one score. The legacy composite = average of the nine scored sections, shown /10 — 8–10 excellent · 6–8 ACCUMULATE · 4–6 WATCHLIST · <4 AVOID — stays a clearly-labelled secondary indicator. WATCHLIST is a verdict word; the status axis stays HOLDING / CANDIDATE.

Cycle: Task A builds a fund; Task B runs monthly (28th–2nd) — refresh NAV/news, RE-PICK peers, refresh tabP/tabR, re-score, append a dated journal row; Task C is an ad-hoc NAV/P&L refresh (price-only, no re-score, no journal row).

Data: Value Research Online only — every figure carries source + date, every NAV its NAV date, unconfirmable figures flagged VERIFY. Glossary: MutualFunds/code/glossary_mf.js.
